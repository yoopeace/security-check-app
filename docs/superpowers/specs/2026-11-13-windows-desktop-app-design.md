# 보안 점검 데스크톱 앱 (윈도우) 설계

작성일: 2026-11-13
상태: 검토 중 (승인 전)

## 1. 왜 만드는가

- 경찰청 치안소프트웨어 공모전에 참가했을 때, 입상작은 모두 데스크톱 앱이었고 웹앱으로 낸 것은 본인 작품뿐이었다.
  다음에는 입상작과 같은 형태로 보여 주고 싶다.
- 실제 업무용 윈도우 PC에 설치해 **인터넷 없이** 돌아가는 앱이어야 한다.
- 쓰는 사람은 **컴퓨터에 익숙하지 않은 동료 직원**이다. 버튼만 눌러 결과를 볼 수 있어야 한다.

## 2. 목표

앱 하나에 탭 두 개.

**로그 분석 탭** (윈도우 이벤트 로그)
- 가) `.evtx` 파일 열기: 수사·점검 대상 PC에서 추출한 보안 로그를 골라 분석한다. 관리자 권한이 필요 없다.
- 나) 이 PC 점검: 지금 쓰는 PC의 보안 로그를 분석한다. 관리자 권한이 있을 때만 쓸 수 있고, 없으면 그 이유를 안내한다.

**파일 무결성 탭**
- 폴더를 고르고 [기준선 만들기] 또는 [검사하기]를 누른다.

**두 탭 공통**
- 결과 맨 위에 판정 하나를 크게: 빨강 "위험 발견" / 노랑 "확인 필요" / 초록 "이상 없음".
- 그 아래에 무엇이 왜 문제인지 쉬운 말로 한 줄씩.
- [보고서 저장]으로 결과를 텍스트 파일로 남긴다.
- 탐지 기준 같은 설정은 기본값으로 고정하고 "고급 설정" 안에 둔다.

## 3. 하지 않는 것 (비목표)

- 인터넷을 쓰는 기능 전부 (AI 해설, 자동 업데이트, 온라인 조회)
- 코드 서명 인증서 구매 (첫 실행 경고는 안내문으로 대응)
- 실시간 감시, 예약 실행
- 맥·리눅스용 배포 (개발 중 맥에서 실행해 보는 것은 가능)
- 업무용 PC에서 개발하기 (업무용 PC는 완성된 실행 파일을 돌려 보는 곳)

## 4. 실패로 보는 것 (반목표)

기능이 돌아가더라도 아래면 실패다.

- **동료가 결과를 잘못 믿게 만드는 것.** 일부를 읽지 못했거나, 분석할 기록이 아예 없거나, 보안 로그가 아닌 파일을 넣었는데
  "이상 없음"을 띄우면 안 된다. 이런 경우는 항상 "확인 필요"와 그 이유를 보여 준다.
  "이상 없음"에도 무엇을 근거로 했는지(분석한 기록 수, 기간)를 함께 적는다.
- **증거를 건드리는 것.** 분석 대상 `.evtx` 파일과 검사 대상 폴더에는 아무것도 쓰지 않는다.
  기준선·비밀키·검사 기록은 앱 전용 폴더(`%LOCALAPPDATA%`)에 둔다.
- **업무용 PC에서 설명 없이 멈추거나 꺼지는 것.** 실패하면 무엇이 안 됐고 어떻게 하면 되는지 한국어로 안내한다.
- **큰 로그에서 화면이 얼어 버리는 것.** 분석은 화면과 따로 돌리고 진행 상황을 보여 준다.

## 5. 제약

- 대상: 윈도우 10·11 업무용 PC, 인터넷 없음, 관리자 권한 없을 수 있음.
- 실행 파일 하나로 실행 (파이썬이 설치돼 있지 않아도 됨).
- 개발은 맥, 윈도우 실행 파일은 GitHub Actions 윈도우 환경에서 생성, 개인 윈도우 PC에서 실제 확인.
- 서명 안 된 실행 파일이므로 첫 실행 때 SmartScreen 경고나 백신 오탐이 생길 수 있다.
- 기존 두 도구(터미널 방식)는 지금처럼 계속 동작해야 한다. 기존 테스트도 그대로 통과해야 한다.

## 6. 방식 (검토한 것과 고른 것)

| 방식 | 장점 | 단점 |
|---|---|---|
| **① CustomTkinter (선택)** | 배우기 쉬움, 실행 파일 약 20MB, 파이썬 기본 화면 도구 기반이라 업무 PC에서 막힐 요소가 적음 | ②보다 위젯이 적음 (표는 tkinter 기본 Treeview로 해결) |
| ② PySide6 (Qt) | 가장 전문적인 겉모습 | 배우기 어려움, 실행 파일 80~150MB |
| ③ pywebview + HTML | 꾸미기 자유로움 | 윈도우 10 업무 PC에 Edge WebView2가 없거나 막혀 있을 수 있음, "웹을 감싼 앱"이라 이번 동기와 어긋남 |

선택 이유: 본인이 공모전 발표·질의응답에서 직접 설명하고 고칠 수 있는 수준이고, 업무 PC 실행 위험이 가장 적다.

개발 환경은 맥(코드·테스트) + GitHub Actions(윈도우 실행 파일 생성) + 개인 윈도우 PC(실제 확인)로 나눈다.

## 7. 정해진 설계

### 7-1. 저장소 구성 (제 판단)

- 새 저장소 `security-check-app`: 화면 코드, 윈도우 이벤트 로그 읽기, 판정 규칙, 실행 파일 빌드.
- 기존 `log-analyzer`, `file-integrity-checker`: 탐지 로직의 원본. 앱은 이 둘을 **복사하지 않고** 불러 쓴다.
  - 두 저장소에 `pyproject.toml`을 추가해 설치 가능한 패키지로 만들고, 버전 태그(예: `v1.0.0`)를 붙인다.
  - 앱은 `requirements.txt`에서 그 태그를 지정해 설치한다. 실행 파일을 만들 때만 인터넷이 필요하고, 만들어진 실행 파일은 인터넷 없이 돈다.
  - 맥에서 개발할 때는 두 저장소를 `pip install -e`(수정 즉시 반영 모드)로 설치해, 도구를 고치면 앱에 바로 반영되게 한다.
- 윈도우 이벤트 로그 읽기는 앱 저장소에 둔다. log-analyzer는 지금처럼 표준 라이브러리만 쓰는 도구로 남는다.

### 7-2. 기존 도구에 필요한 변경

- **log-analyzer**: `analyze()`의 판정 부분(등급별 탐지, 같은 대상 묶기)을 "실패 이벤트 목록"을 받는 함수로 떼어 낸다.
  지금의 줄 단위 입력과 앞으로의 윈도우 이벤트 입력이 같은 판정을 쓰게 하기 위해서다.
  탐지 대상 키는 IP만이 아니라 아무 문자열(예: `계정 admin`)이 될 수 있게 한다.
- **checker**: `create_snapshot()`도 `run_verification()`처럼 결과를 값으로 돌려주는 함수와 화면 출력으로 나눈다.
  앱은 값만 받아 화면에 그린다. 터미널 출력은 지금과 같아야 한다 (30개 시나리오 비교).

### 7-3. 윈도우 이벤트 → 탐지 규칙 (제 제안)

| 이벤트 ID | 뜻 | 판정 |
|---|---|---|
| 4625 | 로그인 실패 | 기존 브루트포스 기준 그대로 적용 (급속 10분 40회, 누적 24시간 8회) → 넘으면 **위험** |
| 1102 | 보안 로그 삭제 | 흔적 삭제 의심 → **위험** |
| 4740 | 계정 잠금 | **확인 필요** |
| 4720 | 새 계정 생성 | **확인 필요** |
| 4732 | 관리자 그룹(SID `S-1-5-32-544`)에 계정 추가 | **확인 필요** |

- 4625의 묶음 기준: 원격 IP가 있으면 IP별, IP가 `-`·`127.0.0.1`·`::1`처럼 이 PC 자신이면 계정별로 센다.
- 이벤트 시각은 UTC로 저장돼 있으므로 판정은 UTC로 하고, 화면에는 한국 시각으로 보여 준다.
- 보안 로그가 아닌 파일(예: System.evtx)이거나 위 이벤트가 하나도 없으면 "이상 없음"이 아니라 **확인 필요**로 보이고 이유를 적는다
  ("보안 로그가 아닙니다", "분석할 로그인 기록이 없습니다. 감사 정책이 꺼져 있을 수 있습니다").
- 읽지 못한 레코드가 있으면 건수를 적고 **확인 필요**.

### 7-4. 이 PC 점검

- 관리자 권한이 있으면: 윈도우 기본 명령 `wevtutil epl Security <임시파일>`로 보안 로그를 임시 `.evtx`로 내보낸 뒤,
  가) 파일 열기와 **같은 경로**로 분석한다. 임시 파일은 분석 후 지운다.
- 관리자 권한이 없으면: 버튼에 "관리자 권한 필요"를 표시하고, 누르면 [관리자 권한으로 다시 실행] 안내와 버튼을 보여 준다
  (윈도우 권한 확인 창을 거쳐 앱을 다시 띄움).

### 7-5. 파일 무결성 탭

- 기준선·비밀키·검사 기록은 `%LOCALAPPDATA%\SecurityCheck\integrity\<폴더 경로의 해시>\`에 저장한다 (일부 도구의 한글 경로 문제를 피하려고 영문 이름 사용). 검사 대상 폴더에는 아무것도 쓰지 않는다.
- 판정: 변조·삭제·추가가 있으면 **위험**, 검사하지 못한 파일이 있거나 기준선을 믿을 수 없으면 **확인 필요**, 그 외 **이상 없음**.
- 결과 목록: "바뀐 파일 / 사라진 파일 / 새로 생긴 파일 / 확인하지 못한 파일"로 표시한다 (해시·종료 코드 같은 말은 쓰지 않음).
- 비밀키를 USB 등 다른 곳에 두는 기능은 고급 설정에 둔다.

### 7-6. 화면과 실행 파일

- 창 제목 "보안 점검 도구", 실행 파일 이름 `SecurityCheck.exe` (제 판단, 공모전 이름이 정해지면 바꿈).
- 밝은 화면 고정, 글꼴은 윈도우 기본 맑은 고딕.
- 분석·검사는 별도 작업으로 돌리고 진행 표시와 [취소]를 둔다. python-evtx는 순수 파이썬이라 큰 보안 로그(수백 MB)는 몇 분 걸릴 수 있다.
- 보고서는 UTF-8 텍스트(.txt), 저장 위치는 사용자가 고른다.
- PyInstaller 한 파일(onefile)로 만든다. 백신 오탐이 잦으면 폴더 묶음(onedir) + zip으로 바꾼다.
- README에 첫 실행 경고 넘기는 방법을 그림과 함께 적는다.

### 7-7. 테스트

- 판정 규칙(이벤트 → 위험/확인 필요/이상 없음), 4625 묶음 기준, 시각 변환은 화면 없이 값으로 테스트한다.
- 이벤트 해석은 직접 쓴 이벤트 XML 문자열로 테스트한다 (`.evtx` 파일 없이).
- `.evtx` 읽기는 작은 예시 파일 하나로 테스트한다 (8절 참고).
- 앱 저장소 CI: 맥·리눅스에서 테스트, 윈도우에서 테스트 + 실행 파일 생성 후 내려받을 수 있게 올림.
- 화면은 개인 윈도우 PC에서 점검표(체크리스트)로 직접 확인한다.

## 8. 사용자에게 필요한 것

- **예시 `.evtx` 파일**: 개인 윈도우 PC에서 테스트용 계정으로 로그인을 몇 번 일부러 틀린 뒤, 이벤트 뷰어에서 보안 로그를 저장한 파일.
  실제 개인 정보가 들어가지 않게 테스트용 계정으로 만든다. 공개 저장소에 올라가므로 이름·PC 이름을 확인한 뒤 넣는다.
- 업무용 PC에서 외부 실행 파일을 돌려 보는 것이 허용되는지 확인 (허용되지 않으면 개인 PC에서만 시연).

## 9. 만드는 사람에게 맡기는 것

- 화면 세부 배치, 색상 값, 문구 다듬기 (위 원칙 안에서)
- 빌드용 파이썬 버전 (3.12 이상, CI와 맞춤)
- 관리자 권한 확인·재실행 구현 방법
- python-evtx 결과(XML)에서 필드를 꺼내는 방법

## 10. 작업 순서 (안)

1. 기존 두 도구 정리: 판정 함수 분리(log-analyzer), 기준선 만들기 값 반환(checker), 패키지화와 태그
2. 앱 저장소 만들기, 윈도우 이벤트 해석과 판정 규칙 (테스트 우선)
3. 화면: 로그 분석 탭 → 무결성 탭
4. 실행 파일 빌드 CI, 개인 윈도우 PC에서 점검
5. README (설치·첫 실행 안내, 화면 캡처)
